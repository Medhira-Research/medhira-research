# Start Here: Your First Steps into Tech

Welcome to Medhira Research.

If you are completely new to computers, coding, or technology, you are in the right place. You do not need a perfect background or a clear career plan before beginning.

## The beginner pathway

```text
Computer basics
      ↓
Coding foundations
      ↓
Git and GitHub
      ↓
Linux and the terminal
      ↓
Explore different fields
      ↓
Choose one direction
      ↓
Build a small project
      ↓
Document your work
      ↓
Ask questions and connect
```

## Step 1: Become comfortable with your computer

Start with:

- Files and folders
- Browsers and search
- Downloads and file types
- Typing and keyboard shortcuts
- Basic digital safety

**First task:** Create a folder named `my-learning` and organise three text files inside it.

## Step 2: Learn coding basics

Choose one beginner-friendly language. Python is a reasonable starting point, but you can also begin with another language required by your course.

Learn these concepts:

- Variables and data types
- Conditions
- Loops
- Functions
- Lists or arrays
- Debugging and reading error messages

**First task:** Write a program that asks for your name and prints a personalised greeting.

## Step 3: Understand Git and GitHub

Learn the difference between Git and GitHub:

- **Git** tracks changes in your files.
- **GitHub** hosts repositories and supports collaboration.

Start with repositories, README files, commits, branches, issues, and pull requests.

**First task:** Create a repository containing one small program and a README explaining what it does.

## Step 4: Try Linux and the terminal

You can begin slowly using Linux, WSL, or a virtual machine.

Practise:

- `pwd`
- `ls`
- `cd`
- `mkdir`
- `touch`
- `cp`
- `mv`
- `cat`

**First task:** Create a directory from the terminal and place a text file inside it.

## Step 5: Explore before specialising

Spend a short, focused period trying different areas:

- Web development
- Backend engineering
- AI and machine learning
- Cybersecurity
- Cloud and DevOps
- Data and analytics
- Game development
- Research
- Open source

Do not remain at the exploration stage forever. After trying a few areas, choose one direction to practise consistently.

## Step 6: Build something small

Your first project does not need to be impressive. It needs to be finished.

Examples:

- A personal webpage
- A command-line calculator
- A notes app
- A simple API
- A beginner data analysis notebook
- A Linux command reference
- A documentation contribution

## Step 7: Document what you learn

For every project, record:

- What you tried
- What worked
- What failed
- What you learned
- What you want to improve next

A clear README is evidence of your learning, even when the project is small.

## Step 8: Ask questions and connect

Talk to classmates, seniors, teachers, and people working in fields you are exploring.

When asking for help:

1. Explain what you are trying to do.
2. Share what you already tried.
3. Include the exact error or doubt.
4. Ask one clear question.
5. Be open to feedback.

There are no useless questions when you are genuinely trying to learn. Be respectful, and do not share passwords, API keys, or private information.

## Your first-week checklist

- [ ] Organise a learning folder.
- [ ] Write one tiny program.
- [ ] Create or improve a GitHub profile.
- [ ] Make your first repository or README change.
- [ ] Try five terminal commands.
- [ ] Explore two technology fields.
- [ ] Write down one direction you want to test next.

## Remember

You do not need to learn everything at once. Start small, finish something, ask questions, and repeat.

**Curiosity starts the journey. Consistent implementation moves it forward.**
